## 3. 分工确认（对 issue #63 的正式答复）

### 3.1 A 对 C 建议的确认

C 提出的 4 项交付**全部保留，边界不变**（`server/src/io/`、`server/src/topology/` + 相关文档），并把接口口径钉死如下，避免与 B 重复开发：

**C → B（压缩模块的输入）**

- 每个模态的拓扑产物：`nodes`（id → `[lat, lon]`）、`edges`（有向边序列）、`wayId → highway`；B 已通过 `buildModalTopology` 的产物消费，无需新通道。
- **属性链一致性**判定所需的 way 边界信息：压缩链一旦跨越等级/限速/方向/权限差异就必须断开，C 提供 way → 属性与准入边界的只读查询。
- 压缩前后拓扑统计（节点数 / 边数 / 各等级里程），供对比报告的拓扑部分。

**B → C（对比报告的输入）**

- 压缩算法结果与**查询耗时**（压缩图 vs 原图），供「压缩效果对比报告」的性能部分；C 不另起重复的性能实验。

**B（对 issue #63 的确认点）**

- 现有拓扑**可直接消费**：`buildModalTopology` 产物 + `wayId → highway` 已足够，不需要 C 新增构图模块或新数据库。
- 仍需 C 提供：属性链边界查询（见上）、压缩前后拓扑统计口径（节点数 / 边数按**有向边**计，与 `/api/health` 的 `edgeCount` 口径一致）。

### 3.2 关键节点：保留还是映射（最小方案）

**判定口径（关键，避免用现有有向度误判）**

度-2 用**去重后的邻居数**判定：`N(v) = { w | 存在边 v→w 或 w→v }`，当 `|N(v)| == 2` 才是可压缩的中间点。
双向道路的普通中间点有向度 = 4（入 2 出 2）但邻居数 = 2，**不能直接拿现有有向度统计判断**——这与 `TopologyStats` 的有向度口径不同，须在实现中显式区分。

**保留集（命中即不压缩，本期最小方案）**

1. **禁转相关节点**：出现在任何禁转边对中的 via 节点（用户当前设置 + OSM relations 导入）。
2. **换乘相关节点**：出现在 A 的换乘连接表中的路网节点 id（**不是设施展示 id**）。
3. **属性变化点**：highway 等级、限速、oneway、权限等影响权重的属性沿链发生变化处。
4. **方向模式变化点**：双向链 ↔ 单向链的切换处。
5. **准入边界点**：模态准入过滤（issue #56）造成的链路端点。

**映射与还原（最小方案）**

- 压缩边记录 `originalEdgeIds`（原图有向边序列）+ 起始/终止原图节点 id；压缩图路径 → 原图路径还原 = 按序列展开并拼接共享的原图节点。
- 权重累计：距离口径直接 Σ 原边长度；时间口径**逐原边算时间再求和**（不先平均速度再乘总长，避免属性差异被摊平）。

### 3.3 禁转编辑后，压缩结果如何更新

- 禁转一律按**原图边对**存储与判定（现有口径不变，SQLite 快照按 way 段端点 + 几何重新匹配，不存易变 edgeId）。
- 禁转集合变化 → 保留集变化 → 压缩结果变化。
- **最小方案：按需惰性重建**。压缩图缓存键 = `(mode, 禁转表版本号)`；禁转被增删改 → 版本号 +1 → 下次取压缩图时失效重建。不做常驻全量缓存，不引入新数据库，不新增持久化表。
- 落库时机：编辑禁转与压缩重建解耦——禁转编辑立即落盘生效，压缩图在下次查询时按新保留集重建，两者在响应里体现为同一时刻的一致结果。

### 3.4 换乘衔接

- 换乘连接表由 A 提供（`buildTransferLinks`），节点为**路网节点 id**；C 的 `inspectTransferEntrances` / `matchTransferConnections` 仍只产出证据与候选，不自动建边，口径不变。
- 压缩时凡出现在连接表中的节点进入保留集，故换乘连接不会被压缩破坏。
