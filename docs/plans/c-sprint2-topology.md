## 2. 第一批模块设计

只从 `@gisalgo/shared` 引用冻结类型，不重新定义 TravelMode、TurnRestriction 等副本。

- 按有向边生成入边/出边索引，避免每次查询路口都扫描百万边。
- 禁转表使用 `Map<viaNode, Map<fromEdge, Set<toEdge>>>`；查询只返回边对是否允许，不以左右标签执行搜索限制。
- 更新路口时先校验全部边对：入口边必须终止于 viaNode，目标边必须起始于 viaNode；无效请求整体失败，旧集合不变。空集合明确表示清除该路口禁转。
- 转向枚举输入当前拓扑、路口与禁转状态，输出 IntersectionTurns，包括全部入边/出边组合与展示字段。
- 方位角采用真实入口行驶方向（入口边起点→路口）和出口行驶方向（路口→出口终点），避免把入口方向算反。angleDelta 归一化区间及 ±180 的约定需在设计中写明并测试。
- left/right/straight/u_turn/ambiguous 的数值阈值先作为项目显示策略提出并测试，不称作通用交通标准；相邻方向容易混淆时应能返回 ambiguous。
- 非有限或零长度方向无法可靠求方位角，不能伪造为直行。先诊断并定义回退；不盲目按米级阈值删边，避免 Float32 精度或合法重合节点导致误删连接。
- only_straight_on 按入口边分别判断，而不是整个路口统一判断。稀疏表仍需保留每个被禁边对；归并展示不能改变搜索实际语义。冻结的 type 与被禁边对如何关联需检查，发现歧义先向 A 请求确认。

拟从 topology/index.ts 暴露的能力：创建/查询/覆盖禁转集合、枚举路口转向。具体函数名称与参数在实现前明确，作为 B/E 的对接说明；不会把尚未实现的方法宣称为可用接口。

## 3. 五路口与持久化

- 从武汉相邻道路与节点筛选五个真实几何方向的候选路口，核对桥隧/匝道，不能用入出边合计数冒充方向数。
- 选择后保存小型测试夹具和来源说明，记录源文件、节点/way ID、坐标及期望转向。人工/模拟禁转应标 manual，不能声称 OSM 原生禁止。
- 固定用例要覆盖 C 稀疏表、B 的 (node,inEdge) 搜索和 E 的 ambiguous 显示；C 的单测通过不等于三层验收完成。
- 持久化不保存 edgeId 作永久身份。优先评估有向道路段的 from/to 节点、wayId 与 viaNode 等稳定标识，并结合几何校验；仅 fromWay/toWay/via 可能存在多段歧义，恢复多匹配时须报告，不任意选第一条。
- 记录数据集/版本及格式版本；道路删除或几何变化时输出恢复失败明细，不静默复用旧图规则。
- 先检查当前 Node 版本及 node:sqlite 支持，不安装数据库或新依赖。最终 SQLite/JSON 选择和取舍写入 docs/ 的多模态设计文档。

## 4. 多模态与转换点

先检查武汉标签覆盖率，再形成 car/walk/bike/bus 的准入矩阵：highway 基线、access 与各模式特定准入、模式方向例外、construction/proposed 等处理；规则参考资料在实现时核实。

不能对四种模式统一复用汽车 oneway 结果；步行、自行车例外与公交专用权限需要独立处理。bus 若仅为允许公交通行的道路图，应明确不等于真实公交线路/班次网络。模式过滤应保留 highway 原义，报告各模式纳入与排除数量。

现有 loader 不提供 POI 节点标签，转换点须检查原始 wuhan.json 或由 C 的 io 提供另行读取能力；不得直接要求 A 修改预处理脚本。TransferPoint 没有 modes 字段，按模式筛选关系可以作为模块内部索引，不擅自修改 shared。

跨模态连接必须对应可解释的实际节点或吸附结果，记录距离与无法匹配的点；只返回地图标记不等于跨模态路径已完成。
