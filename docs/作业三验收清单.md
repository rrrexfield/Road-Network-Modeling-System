## 5. 演示步骤（答辩脚本 · 建议 8–10 分钟）

> 前置：`npm run dev`（首次自动预处理派生数据；服务端 3000、前端 5173）。本机 3000 落在 Windows 排除端口段时，可用环境变量/临时改端口启动（见 §7）。
> 注意：car 的 `data/derived/wuhan-turns.sqlite` 快照存在 missing-segment（§7.6），禁转写入演示请用 `mode=walk`，或先重建派生数据。

1. **压缩规模**：浏览器/终端访问 `GET /api/compression?mode=car`，展示压缩前后节点/边与压缩比；再请求一次说明 `cached=true`。
2. **压缩路径**：选两个真实路口（如 公太里路 `114.3202642,30.5904238` → 沙湖环路 `114.3272223,30.5734786`），请求
   `GET /api/path?from=...&to=...&mode=car&metric=time` 与加 `&compressed=1`，对比 `distance/nodeIds/edgeIds` 完全相同。
3. **禁转重建**：在转向编辑器（或 `PUT /api/intersections/1881981626/turns?mode=walk`）禁掉一个转向 → 路径绕行；
   请求 `GET /api/compression?mode=walk` 展示 `turnVersion` +1 与重建；清空后路径恢复。
4. **交通时间槽**：同一路径请求 `&metric=time&hour=0`、`&hour=8.5`、`&hour=8.5&congestion=off`，展示时间变化与路线切换、关闭拥堵回到基线；重复请求证明确定性。
5. **可达性**：`GET /api/accessibility?origin=12174256913&budget=5|15|30&mode=car`，展示可达节点/里程随预算增长；加 `&hour=8.5` 展示高峰期等时圈收缩。
6. **权重可视化**：右侧权重面板时段模拟滑杆 + 统计面板可达性卡片（E 的着色/动画按 issue #66 接入后演示）。

## 7. 已知边界与答辩问答准备

1. **CH 收缩层次未做**：任务书标为可选加分项，立项文档 §2.2 定「时间富余才启动」，本期不排期。
2. **压缩模式需 `mode`**：压缩图只存在于模态运行时；`compressed=1` 与 `modes=` 同用或缺 `mode` 返回 400。
3. **端点回退**：端点吸附落在被压缩节点时，透明回退原图并返回 `compression.applied=false`，保证结果正确；代价是不享受压缩。
4. **掉头绕行边界**：已把禁转 via 的**一邻域**纳入保留集，覆盖「在 via 相邻节点掉头」的绕行；**多跳**绕行掉头仍可能因压缩而选到合法但非最优的路径。这是度-2 压缩 + 禁转的已知交互，报告见 issue #64 评论。
5. **端到端查询耗时**：吸附是 O(V) 原图扫描（约 0.18 s/次请求），压缩搜索的收益在 API 层被掩盖；搜索内核公平基准 6.25×（B）。后续可给吸附加空间索引。
6. **car 禁转快照陈旧**：本机 `data/derived/wuhan-turns.sqlite` 的 car 数据集存在 `missing-segment`（ordinal 49），服务按设计拒绝覆盖（409），因此 car 的真实禁转写入演示改用 walk；该文件是 gitignore 的派生生成物，重建派生数据即可恢复。
7. **事件场景为空**：`server/src/index.ts` 的 `TRAFFIC_EVENTS` 先传空数组（D 的交付口径允许）；事件影响由 D 的 20 项 traffic 单测与 A 的路由级 closure 测试证明，生产演示可填入具体 wayId 场景。
8. **跨模态未接交通/压缩**：`/api/path?modes=` 的跨模态分支本期不接 `hour` 与 `compressed`（D 的接线项只覆盖单模态）；写入本清单。
9. **可达性口径**：使用基础拓扑 + 模态速度表（与 `/api/stats` 同口径），不按模态准入过滤边集；car/walk 的差异体现在速度而非边集，答辩按此口径讲。
10. **bus 语义不变**：bus 仍只表示「公交通行道路」，不含线路/站序/班次（作业二已冻结）。
