## 5. 演示步骤（答辩脚本 · 建议 8–10 分钟）

> 前置：`npm run dev`（首次会自动跑数据预处理，约 30 s–2 min），浏览器打开 `http://localhost:5173`。
> 建议浏览器缩放 100%、窗口 ≥ 1280×800；底图离线会自动降级为纯色背景，**路网与交互不受影响**。
> 演示前建议先点一次「汽车」模式预热该模态运行时（首次构建约 5 s，之后毫秒级）。

### 0:00–0:40 开场：作业二做了什么（一句话 + 界面全景）

1. 打开页面，指四个区域：**左下角交通模式条**、**左侧「Dijkstra 最短路径」卡**、**左侧「路口转向限制」卡**、**右侧「路网与拓扑 / 权重配置」栏**。
2. 话术：「作业二我们做的是转向限制与多模态路网。转向限制不只是画在图上，它**真的改变路径**；多模态不只是切图层，它能**跨模态换乘**——这两点都是我接下来要演示的。」

> 界面文案对照（现场按这个指）：模式条 `全量 / 汽车 / 步行 / 骑行 / 公交`；选路卡 `Dijkstra最短路径`、`起终点选路`、`优化目标：最快时间 / 最短距离`、`跨模态`（关闭/开启）、`模态顺序` + `清空序列`；转向卡 `路口转向限制`、`五路口示例`、`加载路口`、`清空选择`、`保存禁转`；权重面板 `权重配置`、`全局速度系数`、`重置为默认限速`；统计 `路网与拓扑` → `网络统计` / `拓扑指标` / `等级里程分布` / `边长分布` / `属性完整性`。

### 0:40–2:30 演示 A：转向限制影响路径（评分权重 25%）

> **五路口真实坐标**：`114.29773, 30.59533`（OSM Node `1881981626`，胜利街 × 一元路 交叉口）。
> 现场把地图定位到这里即可，不用找路。

1. 模式条点「**汽车**」。
2. 左侧「**路口转向限制**」卡点标题展开。
3. 点「**五路口示例**」→ 面板列出该路口**全部转向**（左/右/直/掉头 + 模糊转向的「驶入<道路名>（左偏 X°）」），每行右侧标「OSM / 手动」。
4. 说明画面：路口位置出现**金色环**；被禁的转向在路口附近画成**红色弧线**并标「禁 N」。
5. **关键动作**：在「起终点选路」卡里选两个点（**就用五路口附近**，例如从五路口向南一条街走到下一个路口），记下状态栏的「路径 xxx m」。
6. 回到转向编辑器，**勾选一条当前路径正在走的转向** → 点「**保存禁转**」。
7. 画面：路径**立刻重算并绕开**（长度变长、节点变多），状态栏数字变化。
8. 话术：「保存后服务端落盘、路径立即重算——不是客户端假象。清空勾选再保存，路径立刻恢复原样。」（可当场清空再保存一次对比）
9. **补充演示**：把鼠标点向**普通道路**（不是路口）→ 弹出道路属性卡（说明点选路口与点选道路是两条独立交互）。

### 2:30–4:30 演示 B：多模态切换 + 模态转换点（评分权重 25%）

1. 模式条依次点「**步行**」「**骑行**」「**公交**」「**全量**」——每次路网**整体换一套**（道路集合、方向规则、限速速度表都随模态变），**路径也按当前模态重算**（`/api/path` 带 `mode` 时走该模态子图并施加该模态的禁转）。
2. 指地图上的 **M（地铁）/ B（公交站）/ P（停车场）** 标记，说明这是「模态转换点」。
3. 话术：「四个模态是**各自独立构图的子图**，准入规则、方向规则、限速速度表都不同；转换点是两个模态之间的**真实换乘位置**，武汉全量 2930 个转换点能建立 2447 条换乘连接。」
4. **口径说明（如实讲）**：右侧「路网与拓扑」统计面板目前是**全量路网**的口径，不随模态切换重算——作业二的分模态统计属作业三范围；模式切换影响的是**路网图层与路径**。

### 4:30–6:30 演示 C：跨模态路径（作业二最难的一块）

1. 左侧「Dijkstra 最短路径」卡 →「跨模态」开关打开 →「模态顺序」选「**汽车 → 步行**」（≥ 2 个模态）。
2. 地图上取两点（**坐标已对真实地物核实**，可直接照抄）：

   | 角色 | 坐标 [lon, lat] | 对应地物（已用派生数据核实最近道路） |
   |---|---|---|
   | 起点 | `114.30354, 30.56582` | 积玉桥 A 口地铁站旁的点型**停车场**（最近道路：和平大道 81 m） |
   | 终点 | `114.2897, 30.5823` | 江汉路一带（最近道路：鄱阳街/上海路 36 m、江汉路 165 m） |

   起点即「驾车 → 停车场换乘 → 步行」里的停车场，步行段会经过地铁站。
3. 等 10–20 s（首次要建两套模态运行时，**提前说明这是首次预热**）。
4. 画面：**金色段 = 驾车**、**绿色段 = 步行**，两段衔接处有**金色描边的换乘点标记**；状态栏给出分段摘要。
   - 用「**最快时间**」口径（默认）：`汽车 5.9 分钟 → 步行 11.6 分钟 · 换乘 1 处 · 共 22.9 分钟（含换乘等待 5.4 分钟）`
   - 切到「**最短距离**」口径再看一次：`汽车 5.5 km → 步行 774 m · 换乘 1 处 · 共 6.3 km`——**同一段路径，两种口径都能读**，换乘等待只出现在时间口径里。
5. 话术：「这条路径是**跨模态算出来的**：层内用带禁转的边扩展 Dijkstra，层间用动态规划在多个候选换乘点里选全局最优——不是遇到第一个换乘点就换。等待与接驳时间按契约**不计入距离**，单独下发，所以界面里能分开显示。」
6. 可选加演：把「模态顺序」改成「**公交 → 步行**」再算一次，说明换乘点集合随模态对变化。

### 6:30–8:00 演示 D：权重面板与统计（与作业一集成）

1. 右侧栏展开「**权重配置**」→ 拖动「**全局速度系数**」滑杆。
2. 话术：「速度系数与等级限速覆盖是**全局权重参数**，走 `/api/path` 与 `/api/stats` 同一套参数，所以统计面板与路径会同时按新配置重算；而『最快时间 / 最短距离』这个优化目标只留在选路卡一处，避免两个入口改同一个值。」
3. 展开「**路网与拓扑**」→ 展示网络规模、拓扑指标（连通分量 / 最大分量 / 悬挂节点 / 孤立节点 / 平均度）、**属性完整性**条形图（name 18.77%、maxspeed 0.93%）。
4. 话术：「限速只有 0.93% 来自原始标注，其余是按等级推断的——所以所有时间指标都是**估算**，我们在报告和界面里都标注了口径。」

### 8:00–9:30 收尾：核心代码与诚实边界

1. 口头点出三个核心函数（答辩抽问准备）：
   - `server/src/graph/turn-restricted-dijkstra.ts` → `dijkstraWithTurnRestrictions`（边扩展状态空间）

## 7. 已知边界与答辩问答准备（如实口径）

### 7.1 「专用车道（only_*）」到底做到哪一步

- **模型层**：契约 `TurnRestrictionType` 含 `only_left_turn / only_right_turn / only_straight_on / only_u_turn` 8 种类型；
  C 的 `classifyTurnRestrictions` 能把「某入口只剩直行允许、其余全禁」归并为 `only_straight_on`，并有 6 项测试。
- **运行时**：按立项文档 §3.3.2「给机器存对、给人看标签」，**存储与判定一律用边对**，`type` 只作语义说明；
  禁转服务与 REST 接口当前只落边对，编辑器展示的是转向几何（左/右/直/掉头 + 模糊偏角），**不展示 type 列**。
- 如实回答：「专用车道的语义模型与归并逻辑已实现并可测试；运行期按边对存储是设计决策（边对能表达任意 N 路口，类型不能），编辑器按几何展示更直观。」

### 7.2 换乘连接有 1995 条是「几何近似」而非实景核验

- 只有 **452 条**是 `shared-osm-node`（设施自身的 OSM 节点就是该模态图的节点，连接在节点层面精确）。
- 其余 **1995 条**是半径内最近节点（`nearby-candidate`），**没有做实景出入口核验**；way 型设施（停车场、站台面）因缺出入口证据**一律不建连接**。
- 如实回答：「我们宁可少连、也不把连接接到不存在的路上；证据类型随连接一起保留，界面上和文档里都能看到区别。」

### 7.3 换乘等待时间是占位值

地铁 5 分 / 公交 3 分 / 停车 5 分（D 的 `transferPenaltySeconds`），**未标定**；标定需要实景换乘数据与作业三的时间槽模拟。接驳步行时间按 1.3 m/s 换算，数值口径明确。

### 7.4 公交 / 地铁的语义边界

bus 仅表示「公交通行道路」（`motorRoads + busway`），**不含线路、站序、班次、停站规则**；`TravelMode` 没有 rail，地铁站只归属 walk。
故「驾车 → 地铁站 → 步行」在本模型里表现为「驾车 → 换乘点 → 步行（途经地铁站）」，**不代表线路级可达**。答辩口径：作业二证明的是**多模态分离与转换点可行性**，不是公交调度。

### 7.5 跨模态查询的代价

一次跨模态查询要**同时持有两个模态的图与禁转索引**（武汉实测 car + walk 约 2.3 GB 堆），首次查询约 18 s（构建两套运行时 + 连接表 + 两轮边扩展 Dijkstra），之后命中运行时缓存明显更快。换乘连接表按模态集合缓存（全量四模态约 1 s）。

### 7.6 常见抽问

| 抽问 | 回答要点 |
|---|---|
| 为什么转向限制的状态必须是 (节点, 入边)？ | 禁转约束的是 (入边, 出边) 边对。纯节点状态丢失来路信息，支配性剪枝会把唯一可行路径剪掉——到同一路口两条路径（西边 5 分、南边 8 分），剪掉 8 分却留下「经西边左转」被禁的那条。 |
| 跨模态怎么保证是全局最优？ | 层间是动态规划：第 i 层算出到每个候选换乘点的最小代价，作为下一层的多源初始代价，多个候选换乘点取全局最小，不是贪心取第一个。 |
| 换乘连接为什么不允许 way 型设施？ | way 型设施的代表点是包围盒中心，不是出入口；用它连接会接到一条根本不存在的路上。宁可少连。 |
| 属性完整率为什么按 way 统计而不是按边？ | 同一 way 会被拆成多条有向边，按边统计会把完整率重复稀释（6.9 万 way 对应 119 万有向边，差一个量级）。 |
| 限速 0.93% 意味着什么？ | 限速几乎都来自按等级推断，不是原始标注，所以所有时间类指标都是**估算**；报告与界面都标注了口径。 |
| 禁转和路径计算会不会内存分叉？ | 不会：编辑器与路径计算共用同一份 `PersistentTurnService`，保存写盘优先，写盘失败不改旧内存；重启按「way 段端点 + 几何」重新匹配恢复。 |
